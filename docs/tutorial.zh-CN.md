# 教程草稿：扫描件秒变可搜索——给 Claude 装上本地 PDF 引擎

> 投放目标：少数派 / V2EX / 即刻。发布时替换截图与真实仓库链接。
> 标题备选：《为什么我的 Claude 现在能处理扫描合同了》《别再为 OCR 上传文件了：一个本地 PDF MCP 的诞生》

## 正文

### 先说痛点

你大概也遇到过：

1. **扫描件是 Claude 的盲区。** 把扫描的合同、发票、证件 PDF 发给 ChatGPT，十有八九得到一句 "No text could be extracted"。Claude 网页版能"看图"，但 Claude Code 里读 PDF 是按页渲染成图计价的——同一个文件，实测 73,500 tokens，而本地提取文本只要 2,400。**30 倍的差价。**
2. **加密 PDF 直接被拒。** Claude 官方文档写得很清楚：不支持加密 PDF。你手里有密码也没用——客户端根本不给输密码的机会。
3. **云端 OCR 工具要你上传文件。** 合同、病历、证件，传上去心里总归咯噔一下。

这三个问题的共同解法是：**让 AI 在你本机上调 OCRmyPDF / poppler / qpdf 这些十年老将**，而不是把文件送出去。

### 三分钟装好

（此处插入 mcpServers JSON 配置截图 + `brew install poppler qpdf tesseract tesseract-lang` 一行）

装完对 Claude 说一句："帮我看看这个 PDF"。它会先调 `pdf_info` 探路——加密的会提示你先解锁，扫描件会建议先 OCR。缺什么系统依赖，错误信息里直接给你 brew 命令，不用翻文档。

### 场景一：扫描合同变可搜索

"这份扫描的租房合同，帮我找出所有提到违约金的页。"

背后发生的事：`ocr_pdf` 调 OCRmyPDF 把中英文文本层**写回 PDF 文件本身**——不是只读出来给你看一眼，而是产出一个真正可搜索、可复制、能被 macOS Preview 聚焦搜索的新文件。deskew 自动纠偏，已有文本的页自动跳过。

（截图：Preview 搜索命中高亮）

### 场景二：忘了 owner 密码的加密件

"这个 PDF 密码是 xxx，解开然后提取第 3 页文字。"

`unlock_pdf` 只需要 **user（打开）密码**。这听起来理所当然，但我们实测了四个主流 PDF MCP：三个直接报错，最接近能用的那个（ODA）坚持要 owner 密码才肯动权限位，拆出来的文件还是加密的。这里输出的是干净解密文件。

### 场景三：复杂版面直接"看图"

"第 4 页那个表格讲了什么？"

文本提取对付不了复杂表格时，`render_pages` 把页面渲染成 PNG 直接推给多模态模型——它自己看。

### 隐私与边界

- 零网络调用：MCP server 不联网，文件不出机器，这个可以在源码里验证（也欢迎审计）
- 输出永不静默覆盖已有文件；写出可限制在指定目录内
- 改不了 PDF 里的已有文字（那是编辑器的领域）、破解不了没有密码的加密

### 尾声：为什么开源社区没人早做这个？

调研时的发现挺有意思：做 MCP 的程序员不碰扫描合同，被扫描件折磨的人不会写 MCP；Python 开发者本能 `pip install pypdf` 抄近路（没有 OCR）；需要装三个系统二进制的方案在 MCP 目录站永远排在"npx 一行"后面。于是这个空白留到了今天。

项目地址：https://github.com/twoer/pdf-toolbox-mcp 。MIT，欢迎 issue 和 PR。
